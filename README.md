# 提瓦特触控映射 (GenshinTouchMap)

把 FPS 玩家的按键习惯，映射到《原神》手游上。悬浮层自定义按键 + 虚拟摇杆 + 多指同时模拟触摸，免 root。

## 功能

- **自定义按键**：新建任意数量的按键（点击键 / 长按键），拖拽摆放位置，长按进入「选点模式」点击原神中对应按键的位置完成映射
- **虚拟摇杆**：FPS 习惯的移动摇杆，拖动方向与幅度按比例映射到原神的摇杆
- **多指同时操作**：移动 + 瞄准 + 射击 + 跳跃可同时进行（手指状态机 + 全量重建手势）
- **完全隔离**：每个按键是独立的小悬浮窗口，只拦截自己的触摸区域，其余区域透传给游戏

## 技术栈

- Kotlin 2.0 + Compose (Material 3) + coroutines + Flow
- DataStore (Preferences) 配置持久化
- kotlinx.serialization JSON 序列化
- targetSdk 33 (Android 13) / minSdk 26

## 使用方法

1. **安装并打开 App**，依次授予：
   - 悬浮窗权限（点击"去开启"）
   - 无障碍权限（点击"去开启"，找到"提瓦特触控映射（触摸模拟服务）"并打开）
   - 通知权限（Android 13+ 自动弹窗请求）
2. 点「启动悬浮层」
3. 打开原神，屏幕右侧会出现一个悬浮球（点击可在 编辑/运行 模式间切换）
4. **编辑模式**：
   - 拖动按键/摇杆 → 调整摆放位置
   - 长按按键 → 进入选点模式，点击原神里对应按键的位置，完成映射
   - 摇杆长按 → 设置摇杆映射中心（原神移动摇杆的中心）
5. **运行模式**：按键和摇杆正常工作

## 架构

```
MainActivity (Compose 配置界面)
      │  增删改配置
      ▼
OverlayService (前台服务)
  ├── KeyButtonView / JoystickView / FloatBallView  —— 每个按键一个独立 Window 窗口
  ├── 运行模式: 触摸事件 → TouchInjector
  └── 编辑模式: 拖动位置 / 选点映射
      │
      ▼
TouchInjector (引擎抽象接口)
  └── TouchMapperService (无障碍服务 · 引擎 A)
        ├── 手指状态机: fingerId → (x, y)
        ├── 任何变化 → 全量重建 GestureDescription 并 dispatchGesture
        ├── 原地按住用长 duration (6s) + 心跳 (2s) 维持，降低打断频率
        └── move 节流: 位移 > 3px 才重建
```

### 多指方案说明

`dispatchGesture` 每次调用会取消上一个手势，因此采用**状态机 + 全量重建**：
- 按下/移动/抬起任何一根手指 → 重新构造所有手指的完整手势集合并提交
- 未变化的手指用「原地按住 stroke」，移动的手指用「移动 stroke」
- 心跳机制在长按住超时前重新提交，保证按压不中断

## 已知限制（务必阅读）

1. **无障碍方案的物理上限**：每次手指状态变化会短暂"重建"所有手指，未变化的手指会有极短暂的按下中断（毫秒级）。对移动摇杆的连续手感有轻微影响，原神这类 PVE 游戏体感可接受；v2 计划接入 Shizuku 引擎（`InputManager.injectInputEvent`）彻底解决
2. **延迟**：`dispatchGesture` 链路比原生触控多几十毫秒，日常操作无感，射击连招略"肉"
3. **封号风险**：无障碍模拟触摸属于辅助功能范畴（非 root 注入），但米哈游反作弊检测严格，**强烈建议先用小号验证**
4. **未设置映射目标的按键**：运行时按到屏幕 (0,0)，请确保每个按键都完成选点映射
